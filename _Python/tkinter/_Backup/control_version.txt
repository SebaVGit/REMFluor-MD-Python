v40  state.push/snapshot — fix scalar-vs-list resolution (CURRENT)
       - ROOT CAUSE of "Paste Example doesn't fill §9 cells":
              functions/state.py snapshot() and push() both treated
              every CELL_MAP var_name ending with "_<digits>" as a
              list element on the app object.  But §9 holds those
              vars as SCALAR StringVars: app.v_psb_a_1, v_psb_a_2,
              v_psb_a_3, v_psb_a_4 (and similarly for v_psb_kf_*,
              v_psb_mw_*, v_trans_rate_*, v_yield_factor_*).  The
              code did getattr(app, "v_psb_a"), got None (no such
              attr), then silently skipped via `continue`.  Result:
              16 §5/§9 cells were never written back to the UI on
              Paste Example or Load Data.
       - Fix: try the scalar attribute FIRST.  If getattr(app,
              var_name) is a tk.Variable, use it.  Only fall back
              to the list-element form (base + _N) if the scalar
              attr doesn't exist — that path still serves §7 source
              rows and §10 monitoring-well rows.
       - Affected vars now propagate correctly:
            v_psb_a_1..4    (Freundlich "a"  — 4 cells)
            v_psb_kf_1..4   (Freundlich Kf   — 4 cells)
            v_psb_mw_1..4   (PFAS molec. wt. — 4 cells)
            v_trans_rate_3/4, v_yield_factor_3/4 (§5 detailed — 4)
       - Companion backup: _Backup/functions_v40/state.py.

main.py + run_model.py (dashboard year dropdown)
   v87  Symptom: after Run Model, the year dropdown showed only one
        option (the end year, e.g. 2077) and the time-axis felt
        disconnected from §11 "See Results Every".

        Root cause #1: form default v_see_every="100" combined with
        v_yr_start="1977" / v_yr_end="2077" gave a 100-year sim with
        output every 100 years → exactly ONE output point at t=100
        (year 2077).  generate_input_file computes
        npt = see_every / dt = 100 / 0.1 = 1000 = nt, so the Fortran
        solver only writes one output frame.  Fix: v_see_every
        default lowered to "10" so a default-config run produces 11
        dropdown years (1977→2077 in 10-yr steps).

        Root cause #2: _dump_dashboard_state's hard-coded fallbacks
        for E18/E19/E15/V47 didn't match the form's StringVar
        defaults (form: 1977/2077/60/100; dump: 2025/2125/10/5).
        When state was somehow blank, the dashboard would label
        years 2025→2125 even though the form would have shown
        1977→2077.  Fix: dump fallbacks now match the form
        (E18=1977, E19=2077, E15=60, V47=10).  These only kick in
        if state is blank — normally state.snapshot pulls the
        StringVar values, and the user's form values are used
        end-to-end.

        Side effect: the "Approximate Run Time" cell in §2 now
        recomputes against see_every=10 instead of 100; should be
        a tiny adjustment, not a regression.
